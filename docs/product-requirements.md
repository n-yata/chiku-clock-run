## 1. 背景・課題

ブラウザで手軽に遊べるマリオ風 2D 横スクロールアクションゲームを個人プロジェクトとして開発する。  
既存のゲームエンジン（Phaser 3）を活用し、インストール不要・URL アクセスだけで即プレイできる形態を実現する。  
GitHub Pages への静的デプロイにより、サーバー維持コストゼロで誰でも遊べる公開ゲームを目指す。  
バックエンドや外部 API を持たないシンプルな構成とし、開発・保守コストを最小化する。

---

## 2. ゴール・目的

| フェーズ | ゴール |
|---------|--------|
| v0.1（MVP） | 1 ステージを横スクロールで踏破できる最小プレイ可能版を GitHub Pages に公開し、デプロイ動線を確立する |
| v0.2 | 敵キャラクター・コイン・スコア HUD を追加し、「マリオ風アクション」のコア体験を実現する |
| v0.3 以降 | BGM / SE・複数ステージ・タイトル画面・スマホ操作改善など体験を順次拡充する |

**成功基準（v0.2）:** URL を開いたユーザーが説明なしでゲームを開始し、敵を踏みつけコインを集めてゴールまで到達できる。

## 3. スコープ

### 対象範囲

- ブラウザで動作する 2D 横スクロールプラットフォーマー（Phaser 3 ベース）
- プレイヤー操作: キーボード（デスクトップ）+ タッチ操作（スマートフォン）
- ゲーム要素: プレイヤー / 地形 / 敵キャラクター / コイン / ゴール / スコア HUD
- GitHub Pages への静的デプロイ（GitHub Actions による自動ビルド・デプロイ）
- 単一ステージ構成（複数ステージは v0.3 以降）

### 対象外

- バックエンドサーバー・データベース・外部 API
- ユーザーアカウント・セーブデータ永続化
- BGM / SE（v0.3 以降）
- 複数ステージ・ステージセレクト・ワールドマップ（v0.3 以降）
- タイトル画面・ポーズ画面（v0.3 以降）
- ライフ / 残機システム（現状はミス即リスタート）
- 外部アセット（現行はプログラム生成のプレースホルダを使用）

## 6. 非機能要件

### パフォーマンス

- 描画: 60 fps 維持（敵 5 体 + コイン 15 枚 + 地形が同時に存在する状況で）
- 初回ロード: GitHub Pages 上で 5 秒以内（モダン回線・キャッシュなし）
- 入力レイテンシ: キー押下 / タッチから自機反応まで 100 ms 以内（体感）
- バンドルサイズ: `dist/assets/*.js` 合計 1.5 MB 以下（gzip 後は 350 KB 以下目安）

### セキュリティ

- シークレット管理: バックエンド・外部 API が存在しないため API キー等は不要。`.env` は `.gitignore` 対象として防御済み
- 通信暗号化: GitHub Pages の HTTPS 配信に依存（追加設定不要）
- 認証・認可: なし（公開ゲーム）
- 入力バリデーション: ユーザー入力はキーボードイベント・タッチ座標のみ。Phaser テキストに渡す文字列はリテラル定数か数値型に固定
- CSP: `index.html` の `<meta http-equiv="Content-Security-Policy">` で `default-src 'self'` 系を設定し、外部リソース読み込みを禁止

### 可用性

- 動作環境: GitHub Pages（静的ホスティング）。SLO は GitHub サービスレベルに依存
- エラー時フォールバック: 例外発生時も R キー / タッチでリスタート可能な動線を維持
- 無限状態禁止: 落下後に即リスポーン・敵の速度ゼロ事故を起こさない

### 保守性

- ゲーム定数（物理パラメータ・HUD スタイル・テクスチャキー）は `src/config/gameConfig.ts` に集約。シーンファイルへのマジックナンバー直書き禁止
- ステージデータは `src/stages/` に 1 ファイル 1 ステージで配置
- シーン分割（`BootScene` / `GameScene`）でテクスチャ生成とゲームロジックを分離

### 拡張性

- ステージ追加: `src/stages/` にファイルを追加するだけで対応可能
- アセット差し替え: `TEX_KEY` で抽象化済み。`BootScene` の `generateTexture()` を `load.image()` に置換するだけで外部アセット化できる
- ステージ規模拡大時: `StageDefinition` 型のアダプタを経由して Phaser Tilemap（Tiled エディタ）への移行余地を確保

## 7. 制約条件

### 技術的制約

- 対応ブラウザ: 最新 Chrome / Safari / Firefox / Edge
- 対応デバイス: デスクトップ（キーボード）・スマートフォン（タッチ）
- 言語・ランタイム: TypeScript 5.4 / Node.js 20（ビルド環境）
- 必須ライブラリ: Phaser 3.80（追加依存は原則禁止）
- ネットワーク前提: インターネット必須（GitHub Pages 配信）。同一オリジン完結・外部 CDN・外部 API 使用禁止

### 予算・期間制約

- インフラコスト: GitHub Pages 無料プランの範囲内
- 期限: 未定（個人プロジェクト）

### 法的・規制制約

- ユーザーの個人情報を収集しないため GDPR・個人情報保護法の対象外
- 外部アセットを使用しないため著作権問題は発生しない（プレースホルダはプログラム生成）

## 8. 用語定義

| 用語 | 定義 |
|------|------|
| プレイヤー | ユーザーが操作する自機キャラクター（赤い四角のプレースホルダ） |
| タイル | ステージ定義に使う 1 マス単位の文字（`#` 地面 / `P` スポーン / `G` ゴール / `E` 敵 / `C` コイン） |
| HUD | 画面上に常時表示されるコイン取得数等の情報。カメラスクロールに追従しない |
| ゴール | ステージ最終地点のオブジェクト。プレイヤーが触れるとクリア判定 |
| ミス | 敵への横・下接触または落下による失敗。スポーン位置にリセットされる |
| プレースホルダ | 外部アセットが未導入の現状でプログラム生成する色付き四角テクスチャ |
| スポーン | プレイヤーの初期出現位置。ミス時はここに戻る |

> 詳細は `docs/glossary.md` を参照。

## 9. リスクと対策

| # | リスク | 影響度 | 発生確率 | 対策 |
|---|-------|-------|---------|------|
| R-001 | Phaser 3 の破壊的バージョンアップ | 中 | 低 | `package.json` でバージョンを固定し、アップグレードは計画的に行う |
| R-002 | GitHub Pages の可用性低下 | 中 | 低 | GitHub サービスレベルに依存。代替ホスティング（Netlify / Vercel）への移行余地を確保 |
| R-003 | バンドルサイズ増大によるロード遅延 | 低 | 中 | 追加依存なし方針を徹底。ビルド時のサイズ監視（`npm run build` 出力確認） |
| R-004 | スマホタッチ操作の操作性不足 | 中 | 高 | タッチ操作 UI の継続的改善（v0.3 以降でバーチャルボタン等の導入を検討） |

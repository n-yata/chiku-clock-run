---

## 1. 背景

### 1.1 現状

- 現在 (v0.8) はミス（敵接触・落下）の際、即座に同ステージ先頭にリスポーンする（`fullRestart()`）
- 残機の概念がなく、何回失敗しても同じステージを繰り返せる
- 「緊張感・やり直しのコスト」がゼロのため、ゲームとしての面白さに欠ける
- プレイヤーは常に「小」状態で固定。サイズ変化・追加ダメージ耐性は未実装

### 1.2 やりたいこと

**残機制（ライフシステム）** と **キノコ（きのこ）パワーアップ** を追加し、  
マリオ風アクションらしい「大きくなれる・ライフを失うとゲームオーバー」のコア体験を実現する。

スコープ外（後続スプリントに送るもの）: ファイアフラワー・スター等の追加パワーアップ、  
セーブデータ（ライフ残数の永続化）、ステージセレクト画面。

---

## 2. ゴール

### 2.1 主目的

- ミスのコストが生まれ、プレイヤーが「慎重に進む」インセンティブを持つ
- キノコを取ることで「大きくなる」喜びと「1 回被弾を耐えられる」戦略性が生まれる
- ゲームオーバーからの再挑戦という明確なフローが完成し、「ゲームとして遊べる」完成度になる

### 2.2 副次目的

- パワーアップアイテムの仕組みを土台として、将来のファイアフラワー等に拡張しやすくなる
- プレイヤースプライトの「大小」状態管理により、アニメーション表現の幅が広がる

---

## 3. スコープ

### 3.1 含むもの

- **残機 HUD**: 画面左上に「♥ × N」を表示（初期残機 = 3）
- **ライフシステム**: ミスのたびに残機 −1。0 になったらゲームオーバー画面へ
- **ゲームオーバー画面**: "GAME OVER" テキスト表示 → 数秒後にタイトルへ戻る
- **キノコアイテム**: ステージデータに新タイル `M` を追加。プレイヤーが接触すると「大」状態になる
- **プレイヤー状態（小 / 大）**:
  - 「小」: 現状通り。敵接触・落下でライフ −1
  - 「大」: スプライトサイズ拡大。敵接触で「小」に戻る（ライフ減算なし）。落下はライフ −1
- **既存機能の温存**: 3 ステージ進行・BGM/SE・タッチ操作・タイトル画面はすべて維持

### 3.2 含まないもの

- ファイアフラワー・スター・無敵状態（後続スプリントで検討）
- ライフ残数のセーブ（localStorage 等への永続化）
- ステージセレクト・ワールドマップ
- ゲームオーバー後に途中ステージから再開する「コンティニュー機能」

---

## 4. 機能要件

### 4.1 ライフシステム

1. ゲーム開始時（タイトル → ステージ1）にライフ = 3 で初期化する
2. ミス発生時: ライフ −1 → ライフ > 0 ならミスアニメーション後に同ステージ再スタート
3. ライフ −1 後にライフ = 0 ならゲームオーバー画面へ遷移する
4. ゲームオーバー画面: "GAME OVER" テキストを表示し、`ALL_CLEAR_TO_TITLE_DELAY_MS` 待機後にタイトルへ
5. ステージ間を跨いでライフ数を引き継ぐ（ステージ遷移で残機リセットしない）
6. ライフ数は `GameScene.init(data)` の `data` として受け渡す（`{ stageIndex, lives }` 形式）

### 4.2 キノコパワーアップ

1. ステージデータにタイル `M`（キノコ）を追加できるようにする
2. `buildStage()` バリデーションに `M` を追加（0..5 個の範囲）
3. キノコは StaticGroup で配置。プレイヤーとの overlap で取得・消滅
4. 取得時: プレイヤーを「大」状態にする。SE を再生する（`mushroom`）
5. 「大」状態では: スプライトの表示サイズを拡大（例: 幅 × 1.5、高さ × 1.5）
6. 「大」状態で敵接触: プレイヤーを「小」に戻す（ライフ減算なし）。一定時間無敵（点滅演出）
7. 「大」状態で落下: 「小」に戻してライフ −1（もしくはライフ −1 のみ。設計時に確定）

### 4.3 HUD 更新

1. ライフ HUD: 「♥ × N」を `HUD_COIN_Y` より上（例: コインラベル上）に表示
2. ライフが減るたびにリアルタイムで更新する
3. 既存のコイン HUD・ステージ HUD との Y 座標が重ならないように再配置する

### 4.4 既存機能の互換要件

- 複数ステージ進行（`stageIndex` 引き継ぎ）は引き続き動作すること
- タッチ操作・BGM/SE・アニメーションは変更なし
- `buildStage()` の既存バリデーション（P/G/E/C の制約）は変更しない。`M` のみ追加

---

## 5. 非機能要件

### 5.1 パフォーマンス

- キノコ追加後も 60fps 維持（stage03 で敵 8 体 + キノコ最大 5 個が同時存在する状況）
- 「大」状態スプライト拡大で描画負荷が増えないこと（`setDisplaySize` のみで対応）

### 5.2 信頼性

- ライフ数が 0 を下回らない（ガード処理必須）
- 「大」状態の無敵フレーム中に多重ダメージが入らない（点滅中は敵 overlap を無視）

### 5.3 互換性・依存

- フロント: Phaser 3.80 の既存 API のみ使用。追加ライブラリ禁止
- ハードコーディング禁止: 初期ライフ数・無敵時間・キノコスプライトサイズ等の定数は `src/config/gameConfig.ts` に集約

### 5.4 セキュリティ

- バックエンドなし。外部 API・ユーザー入力の保存なし
- ステージデータ拡張（タイル `M`）は既存バリデーションに統合するだけで XSS / Injection の余地なし
- クルトワ（security-engineer）レビュー必須（コミット前）

---

## 6. 制約・前提条件

- Phaser 3.80 の `physics.add.staticGroup`・`setDisplaySize`・`setTint` 等の既存 API で実装する
- キノコのスプライトは現行と同様にプログラム生成（`BootScene` で `generateTexture`）とする。外部アセット導入は本スプリント外
- `M` タイルの各ステージへの配置は実装フェーズでバルベルデ・モドリッチが判断する（レベルデザインは設計書で確定）
- コミット前は必ずクルトワ（security-engineer）レビューを実施すること

---

## 7. 受け入れ条件

- [ ] ゲーム開始時にライフ = 3 で始まり、HUD に「♥ × 3」が表示される
- [ ] ミスのたびにライフが 1 減り、HUD がリアルタイム更新される
- [ ] ライフが 0 になると "GAME OVER" が表示され、タイトルへ遷移する
- [ ] ステージをクリアしてもライフ数が引き継がれる（stage1 で残機 2 → stage2 でも残機 2）
- [ ] キノコを取るとプレイヤーが「大」状態になる（スプライト拡大 + SE 再生）
- [ ] 「大」状態で敵に当たると「小」に戻る（ライフ減算なし）
- [ ] 「大」状態で敵に当たった直後は一定時間無敵（点滅演出）で多重ダメージを防ぐ
- [ ] 落下ミスはライフ −1（「大」「小」問わず）
- [ ] 既存の 3 ステージ進行・BGM/SE・タッチ操作・タイトル画面が壊れていない
- [ ] `npm run build` が TypeScript エラーなしで通る
- [ ] クルトワ（security-engineer）レビューで Critical/High なし

## 1. 背景

### 1.1 現状

- v0.1（2026-05-04 リリース、コミット `d017735` 時点）で「1 ステージを左右移動 + ジャンプで進み、ゴール踏破でクリア」までが GitHub Pages 上で稼働。動作確認問題なし
- 実装範囲（v0.1）:
  - `src/config/gameConfig.ts` … 物理定数・寸法・色を集約
  - `src/stages/stage01.ts` … タイル文字列によるステージ定義（`#` 地面 / `P` スポーン / `G` ゴール）
  - `src/scenes/BootScene.ts` … プレイヤー / 地面 / ゴールのプレースホルダ動的生成
  - `src/scenes/GameScene.ts` … ステージ構築・横スクロール・落下リスポーン・ゴール判定・最小タッチ操作（左右 + ジャンプ）・`window.location.reload()` リスタート
- スコープ外で送られたもの: 敵 / コイン / スコア / 残機 / BGM / 複数ステージ / タイトル画面（v0.1 requirements.md §3.2）
- 現状の遊び心地: 「動くけど敵がいない＝マリオ風アクションのコア体験になっていない」

### 1.2 やりたいこと

「マリオ風」のコア体験である**敵を踏みつけて倒す**を中心に、**コイン取得**と**スコア表示**を v0.2 として追加する。複数ステージ・タイトル画面・BGM は v0.3 以降に送る。

---

## 2. ゴール

### 2.1 主目的

- ステージ内に敵が徘徊しており、**踏みつけで倒せる / 横・下から触れるとミス**になる
- ステージ内にコインが配置されており、**取得すると取得数が画面に積算表示**される
- ゴール踏破時、クリア表示と一緒に**「コイン: X / Y」のスコア結果**が表示される
- ターゲット値:
  - Before（v0.1）: 敵 0、コイン 0、スコア概念なし
  - After（v0.2）: 敵 3〜5 体、コイン 8〜15 枚、ゴール時にスコア表示

### 2.2 副次目的

- 敵 / コインを「ステージ定義の追加文字」で配置する設計を確立し、v0.3 の複数ステージ追加コストを下げる
- 「動的に生成・破棄される Sprite」の扱い（敵の倒し演出・コイン取得時の消滅）パターンを確立し、後の SE / アニメ拡張の土台にする
- ミス → リスタートの動線を、v0.1 のゴール時リスタートと**統一フロー化**する（`window.location.reload()` ではなく `scene.restart` 系への移行検討、または現状方式の継続を含めて design.md で決める）

---

## 3. スコープ

### 3.1 含むもの

- 敵キャラクター（クリボー風 1 種類）:
  - 左右に徘徊（壁・地面端で反転）
  - プレイヤーが**上から踏むと倒れる**（消滅 + プレイヤーは小ジャンプ）
  - プレイヤーが**横 / 下から触れるとミス**（ステージ最初からやり直し）
- コイン（1 種類、静的配置）:
  - プレイヤーが触れると取得（消滅 + 取得数 +1）
- スコア HUD:
  - 画面左上に「コイン: 取得数 / 総数」を `setScrollFactor(0)` で常時表示
  - ゴール時のクリア表示に最終スコアを併記
- ステージ定義の拡張:
  - `stage01.ts` に新タイル文字 `'E'`（敵スポーン）/ `'C'`（コイン）を追加
  - 既存の `'#' / 'P' / 'G'` は仕様維持
- BootScene の拡張: 敵 / コイン用プレースホルダテクスチャの動的生成（外部アセット非使用方針を継続）
- ミス → リスタートの動線統一（design.md で方式決定）
- 影響を受けるファイル: `src/config/gameConfig.ts`, `src/stages/stage01.ts`, `src/scenes/BootScene.ts`, `src/scenes/GameScene.ts`

### 3.2 含まないもの

- 複数ステージ・ステージセレクト（v0.3 候補）
- BGM / SE（v0.3 以降）
- タイトル画面・ポーズ画面（v0.3 以降）
- ライフ / 残機システム（ミスは即リスタートで簡素化）
- 敵キャラクターの複数種類（亀風・パックンフラワー風など）
- 敵を倒した時のスコア加算（コイン取得数のみで集計、敵スコアは v0.3 で検討）
- パワーアップ（キノコ等）
- 落下時のミス演出強化（v0.1 の即リスポーンを踏襲、ただしスコアリセット挙動は §4.4 で定義）
- 外部アセット（プレースホルダの色付き四角を継続）
- 永続的ドキュメント（`docs/`）の大規模整備（`functional-design.md` 等の新規起こしは v0.3 以降に送る）

## 4. 機能要件

### 4.1 ゲームプレイフロー（v0.1 からの差分）

1. 既存通り `BootScene` → `GameScene` 遷移（プレースホルダ生成にコイン / 敵を追加）
2. `GameScene.create()` でステージ定義を解釈し、地形 + ゴール + **敵 + コイン**を配置
3. 画面左上に**コイン HUD**（「コイン: 0 / N」）と既存操作ヘルプを表示
4. プレイヤーは左右移動 + ジャンプ（v0.1 の操作系を維持、キーボード + タッチ両対応）
5. **コイン接触**: コイン消滅 + HUD カウント +1
6. **敵との接触**:
   - プレイヤーの y 速度が下方向（落下中）かつ接触位置が敵の上半分 → 敵消滅 + プレイヤーに小ジャンプ反力
   - それ以外（横 / 下から接触） → ミス（§4.4）
7. ゴール接触で v0.1 同様クリア表示。クリア表示には**「コイン: X / Y」のスコア行を追加**
8. リスタート操作（R キー / タップ）で初期状態に戻る（コイン取得数も 0 にリセット）

### 4.2 ステージ定義の拡張

- v0.1 の `StageDefinition` 構造を**踏襲・拡張**:
  - 既存タイル: `'.' | '#' | 'P' | 'G'`
  - 追加タイル: `'E'`（敵スポーン）/ `'C'`（コイン）
  - 追加バリデーション（`buildStage()` 内）: `'E'` の個数 1 件以上 / `'C'` の個数 1 件以上、上限は design.md で決定
- `STAGE_01` の更新:
  - 敵: 3〜5 体、地面の上に配置（空中浮遊禁止）
  - コイン: 8〜15 枚、ジャンプして取れる位置 / 段差の上 / 隙間越えのご褒美など適切に分散

### 4.3 スコア仕様

- 集計対象: コイン取得数のみ（敵撃破は v0.2 ではスコア対象外、§3.2）
- 表示:
  - HUD: 「コイン: {取得数} / {ステージ内総数}」を画面左上に常時表示（カメラスクロールに追従しない）
  - クリア表示: 既存のクリア文言の下に「コイン: {取得数} / {ステージ内総数}」を表示
- リスタート時の挙動: 取得数を 0 にリセット（ミスでも、R キーでも、ゴール後でも同じ）

### 4.4 ミス時の挙動

- ミス発生条件:
  - 敵に横 / 下から接触（§4.1.6）
  - 落下（v0.1 の `FALL_THRESHOLD_Y` 超過、既存挙動を維持）
- ミス発生時の処理:
  - プレイヤー位置をスポーン位置に戻す
  - **コイン取得数を 0 にリセット**
  - **取得済みコインも復活**（ステージを完全初期化）
  - **倒した敵も復活**
  - 落下時の挙動も上記に統一（v0.1 ではコイン概念がなかったため、今回統一する）
- 演出: 残機 / ライフがないため、ミス → 即リセット。短いフラッシュ演出（〜200ms）の有無は design.md で決定
- 全ステージ初期化の実装方式（`scene.restart()` か `window.location.reload()` か、または個別リセット関数か）は design.md で決定

### 4.5 既存機能の互換要件

- v0.1 の物理定数（`GRAVITY_Y=800`, `PLAYER_SPEED=200`, `JUMP_VELOCITY=-450`）は出発点として維持。プレイ感調整のための微修正は許容（敵踏みつけのリアクション速度との兼ね合いで `JUMP_VELOCITY` を多少触る可能性あり）
- v0.1 の操作系（キーボード ←/→/Space/↑/R + タッチ）は仕様維持
- v0.1 のゴール判定 / クリア表示 / 横スクロールカメラ追従は仕様維持
- `vite.config.ts` の `VITE_BASE_PATH` 経由 base 解決は維持
- BootScene のプレースホルダ動的生成方針は継続（外部アセット非使用）

## 5. 非機能要件

### 5.1 パフォーマンス

- 描画: 60 fps を維持（敵 5 体 + コイン 15 枚 + 地形が同時に存在する状況で）
- 初回ロード: GitHub Pages 上で 5 秒以内（v0.1 と同等を維持）
- 入力レイテンシ: 体感 100 ms 以内（v0.1 と同等を維持）
- バンドルサイズ: 1.5 MB 以下を維持（追加依存なし方針のため達成見込み）

### 5.2 信頼性

- 敵の徘徊が壁や段差端で停止せず、無限往復を維持（速度ゼロ事故を起こさない）
- 敵 / コインのリスポーン処理に漏れがなく、ミス → 復帰後に「敵が消えたまま」「コインが消えたまま」が発生しない
- ゴール接触と敵接触が同フレームで発生した場合、**ゴールを優先**（クリア成立を優先する仕様）
- ミス連発で操作不能になった場合、R キー / タップで必ずリスタート可能

### 5.3 互換性・依存

- フロント: TypeScript 5.4 + Vite 5.2 + Phaser 3.80（**追加依存なし**を維持）
- 対応ブラウザ: 最新 Chrome / Edge / Firefox / Safari + モバイルブラウザ（v0.1 のタッチ対応を維持）
- ハードコーディング集約先:
  - 敵 / コインの寸法・色・速度 → `src/config/gameConfig.ts`
  - 敵 / コインの配置 → `src/stages/stage01.ts`（タイル文字列）
  - スコア表示文言 → `gameConfig.ts` または `GameScene` 内の定数（design.md で決定）
  - URL / シークレットは本スプリントでも発生しない（バックエンドなし継続）

### 5.4 セキュリティ

- バックエンドなし、外部 API 呼び出しなし、ユーザー入力はキーボード + タッチのみ → 攻撃面は v0.1 と同じく最小
- ステージ定義は静的データ（ユーザー入力由来ではない）→ XSS / Injection の混入面は引き続きなし
- HUD / クリア表示は静的文字列 + 数値（取得数）のみ。Phaser Text への動的文字列挿入時に**型を数値に固定**してインジェクション余地をなくす
- 外部 CDN・外部アセットの新規読み込みなし

## 6. 制約・前提条件

- バックエンドを持たない静的サイト方針（`CLAUDE.md` / `docs/architecture.md` 準拠）を維持
- ハードコーディング禁止: 物理定数・敵 / コイン仕様・ステージ定義は `src/config/` `src/stages/` に集約
- 永続的ドキュメント（`docs/architecture.md` `docs/repository-structure.md`）の更新は最小限（敵 / コイン追加で構造が変わる箇所のみ追記）
- コミット前にクルトワ（security-engineer）レビュー必須（CLAUDE.md ルール）
- 各ドキュメント（requirements / design / tasklist）はシャビ承認後に次フェーズへ進む
- dev サーバーは自分から起動しない（auto memory `feedback_no_dev_server.md`）。動作確認は Pages デプロイ後にシャビが行う
- 公開対象: GitHub Pages（プライベートデータなし、誰でも閲覧可能）

## 8. 未確定事項（design.md でバルベルデと協議）

- **Q1.** 敵の徘徊反転の検出方式: (a) 地面端のセンサー Sprite を置く / (b) `body.blocked.left/right` で壁衝突反転 + 段差端は事前計算で「歩ける範囲 X 区間」を持たせる / (c) raycast 風に毎フレーム前方の地面有無をチェック。実装コストと挙動の自然さのバランス
- **Q2.** 踏みつけ判定の実装: (a) `overlap` コールバック内で `player.body.velocity.y > 0` かつ `player.bottom < enemy.center.y` を判定 / (b) 敵の上面に薄い当たり判定 Sprite を別途置く / (c) `collider` で物理衝突させ、衝突法線で上下を判定。Phaser 3 のお作法としてどれが堅牢か
- **Q3.** ミス時のステージ完全初期化方式: (a) `this.scene.restart()` を使う / (b) v0.1 の `window.location.reload()` を継続 / (c) 個別リセット関数（敵 / コイン / プレイヤーを個別に戻す）。v0.1 では `scene.restart()` で問題があり `window.location.reload()` に移行した経緯（コミット `d017735`）があるため、その問題が再現しないことの確認込み
- **Q4.** 敵 / コインのプレースホルダ仕様: 色・サイズ・形（敵: 茶色 28×28 四角 / コイン: 黄色 16×16 四角 など）。視認性とプレイヤー（赤 32×48）との区別が付くこと
- **Q5.** ゴール接触と敵接触の同フレーム発生時の優先順位制御: (a) コールバック登録順で暗黙制御 / (b) `isCleared` フラグで明示的にスキップ / (c) Z 順 / Group 分離で物理的に分離。仕様としては「ゴール優先」と決まっているがコード上の実装手段
- **Q6.** ミス演出の有無: (a) 即リセット（演出なし） / (b) 200ms 程度の画面フラッシュ → リセット / (c) プレイヤーの色を一瞬変える程度。v0.2 のシンプルさ優先か、最低限の体験向上か
- **Q7.** クリア / ミス時のリスタート操作（タッチ環境）: タッチ用にも「リスタートボタン」を出すか、画面どこでもタップでリスタートか。v0.1 の現状実装を Read して整合を取る

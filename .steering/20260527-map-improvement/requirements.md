# 要求内容

## 概要

能力取得でプレイヤーが大きくなった後も進行不能にならないステージ地形へ修正する。あわせて、ステージ 1 から 3 に進むほど操作上の挑戦が段階的に高くなるマップ構成へ改善する。

## 背景

現状は、ぜんまいまたはパルスコア取得後の大きなプレイヤーが通れない通路が存在し、能力取得が進行阻害になり得る。また、3 ステージを備えている一方で、プレイ中に感じる難易度差が乏しく、ステージ進行による達成感が弱い。

本変更では、能力が不利益にならない通行可能性を保証しつつ、敵配置・足場構成・移動要求の段階差でステージごとの役割を明確にする。

## 実装対象の機能

### 1. 拡大状態でも通行可能な必須ルート
- `small` / `big` / `fire` のいずれのプレイヤー状態でも、各ステージのスポーン地点からクロックビーコンまで到達可能な必須ルートを維持する。
- `big` / `fire` 状態の表示・物理寸法を基準に、必須ルート上に屈んでも通れない低い天井や閉じ込め箇所を作らない。
- 能力アイテム取得地点から先で、取得した能力を失わない限り進めない構造を解消する。

### 2. ステージ進行に応じた難易度上昇
- ステージ 1 は操作と能力取得に慣れる導入ステージとして扱う。
- ステージ 2 はステージ 1 より、敵・段差・ジャンプ要求などの危険要素を増やした中間難度とする。
- ステージ 3 はステージ 2 より高い危険要素または複合的な突破要求を持つ最終ステージとする。
- 難易度の段階差は、設計時に定義する客観的な評価項目で `stage01 < stage02 < stage03` と確認できるようにする。

### 3. 既存プレイ体験との整合
- 現在の時計工房テーマ、能力物、ビーコンによる進行、3 ライフ、BGM / SE、タッチ / キーボード操作は維持する。
- ステージ定義は既存の `StageDefinition.tiles` による管理を継続し、新たな外部アセットや外部通信は追加しない。
- 現行仕様を示す永続ドキュメントに、通行可能性制約と難易度勾配の方針を反映する。

## 受け入れ条件

### 拡大状態でも通行可能な必須ルート
- [ ] 各ステージについて、必須進行ルートの床上クリアランスが `big` / `fire` 状態のプレイヤーに必要な高さを満たす。
- [ ] 能力取得後の `big` または `fire` 状態で通路に詰まる箇所がないことを、ステージ定義に対する自動検証または実プレイ経路 E2E で確認できる。
- [ ] プレイヤー状態変更、接地判定、既存の能力取得・ビーコン到達フローに回帰がない。

### ステージ進行に応じた難易度上昇
- [ ] 設計で定義した危険要素の評価結果が `stage01 < stage02 < stage03` となる。
- [ ] ステージ 1 は導入用、ステージ 2 は中間難度、ステージ 3 は最終難度として、地形または障害機配置の違いがコード上で確認できる。
- [ ] 各ステージがクリア可能で、Stage 01 から Stage 03 までの進行フローが維持される。

### 既存プレイ体験との整合
- [ ] `npm run typecheck`、`npm run build`、`npm run test:e2e` が成功する。
- [ ] `docs/product-requirements.md`、`docs/functional-design.md`、`docs/development-guidelines.md` が変更後のマップ制約と難易度方針に整合する。

## 成功指標

- 能力を取得したことが理由でクリア不能になる必須ルートを 0 件にする。
- 難易度評価の順序が全 3 ステージで単調増加となる。
- 既存の能力・ステージ進行 E2E を維持し、新しいマップ制約の回帰検証を追加する。

## スコープ外

以下はこのフェーズでは実装しない:

- ステージ数の追加、ワールドマップ、ステージセレクトの実装
- プレイヤーの縮小操作やしゃがみ動作など、新たな回避操作の追加
- 能力効果、操作方式、敵 AI、音響、外部アセット方式の全面変更
- リポジトリ名や公開 URL の変更

## 永続ドキュメントへの影響

- `docs/product-requirements.md`: 能力取得後の通行可能性とステージ難易度勾配を現行要求として追記する。
- `docs/functional-design.md`: ステージ定義の設計制約および検証対象を追記する。
- `docs/development-guidelines.md`: 拡大状態の通路クリアランスと難易度設計・テストのルールを追記する。
- `docs/architecture.md` / `docs/repository-structure.md` / `docs/glossary.md`: 技術構成・配置・用語の変更は伴わないため、現時点で更新不要と判断する。

## 1. 背景

### 1.1 現状

v0.7 時点では以下の課題が残っている:

- プレイヤーは単一静止スプライト（`player.png`）のみ。移動中・ジャンプ中も同じ見た目のため、アクション感が乏しい。
- コイン表示サイズ `24×24 px`、敵表示サイズ `36×36 px` は TILE_SIZE=32 に比べて小さく、視認性が低い（直近 `73f7587` で改善済みだが、まだ足りない）。
- 踏みつけ判定ロジックが `pBody.bottom <= eBody.top + STOMP_TOLERANCE_PX (6px)` の固定しきい値のため、プレイヤーと敵の高度差が大きいとオーバーラップ発生時に既に body が食い込んでおり、ゲームオーバーになってしまう。

### 1.2 やりたいこと

1. プレイヤースプライトにマリオ風の歩行（2フレーム）・ジャンプアニメーションを追加する。
2. コイン・敵の表示サイズを拡大し、視認性を向上させる。
3. 踏みつけ判定を高度差に依存しない方式に修正し、どの位置からジャンプしても踏みつけが成立するようにする。

スコープ外: ライフシステムの追加は今回行わない。

---

## 2. ゴール

### 2.1 主目的

- プレイヤーのアニメーション追加によって「操作しているキャラクターが動いている」体験を実現する。
- コイン・敵の視認性改善: 画面上で一目で認識できるサイズにする。
- 踏みつけバグ解消: 高い段差からジャンプして踏んでもゲームオーバーにならない。

### 2.2 副次目的

- プログラマティックなスプライトシート生成パターンを確立し、将来の追加アニメーションの土台にする。

## 4. 機能要件

### 4.1 プレイヤーアニメーション・敵アニメーション共通方針

プレイヤー・敵ともに Canvas API でプログラマティックにスプライトシートを生成し、`textures.addCanvas` で Phaser に登録する。外部アセット追加なし。

### 4.2 プレイヤーアニメーション

1. BootScene の `create()` でプレイヤー用 4 フレームスプライトシートを Canvas API で生成する。
   - フレーム 0: idle（静止）
   - フレーム 1: walk1（左足前）
   - フレーム 2: walk2（右足前）
   - フレーム 3: jump（ジャンプ姿勢）
2. GameScene の `create()` でアニメーション定義を登録する。
   - `player_idle`: フレーム 0、ループ
   - `player_walk`: フレーム 1 → 2、frameRate 8、ループ
   - `player_jump`: フレーム 3、ループなし
3. GameScene の `update()` で状態に応じてアニメーションを切り替える。
   - 着地中・停止: `player_idle`
   - 着地中・移動: `player_walk`
   - 空中: `player_jump`
4. 移動方向に応じてスプライトを左右反転（`setFlipX`）する。

### 4.3 敵アニメーション

1. BootScene の `create()` で敵用 2 フレームスプライトシートを Canvas API で生成する。
   - フレーム 0: walk1（通常歩行・左足前）
   - フレーム 1: walk2（歩行・右足前）
2. GameScene の `create()` でアニメーション定義を登録する。
   - `enemy_walk`: フレーム 0 → 1、frameRate 6、ループ
3. 敵スプライト生成時に `enemy_walk` を自動再生する。
4. 向き（`dir`）に応じてスプライトを左右反転（`setFlipX`）する（`updateEnemyAi` 内）。

### 4.4 コイン・敵サイズ拡大

- `COIN_SPRITE_W / H`: `24 → 32` px
- `ENEMY_SPRITE_W / H`: `36 → 44` px（TILE_SIZE=32 の 1.375 倍）

サイズ変更は定数変更のみで既存の配置・当たり判定ロジックには手を加えない。

### 4.5 踏みつけ判定バグ修正

現行ロジック:
```
pBody.velocity.y > 0 && pBody.bottom <= eBody.top + STOMP_TOLERANCE_PX
```
修正後ロジック:
```
pBody.velocity.y > 0 && pBody.centerY <= eBody.centerY
```
「下方向速度を持ちながら、プレイヤーの重心が敵の重心より上にある」を踏みつけ条件とすることで、高度差によるオーバーラップ量に依存しない判定を実現する。

### 4.6 既存機能の互換要件

- コイン取得・SE 再生、敵反転 AI、HUD コイン表示、タッチ操作、BGM/SE はすべて動作を維持する。
- スポーン位置計算（`PLAYER_SPRITE_H` 使用）は変更しない。

## 5. 非機能要件

### 5.1 パフォーマンス

- スプライトシート生成は BootScene の `create()` で同期的に完了させ、ゲーム開始前のロード時間に吸収する。追加の非同期処理は導入しない。

### 5.2 信頼性

- スプライトシート生成に失敗した場合は既存の `player.png` フォールバックは持たず、エラーをそのまま伝播させる（開発時に即検出できる）。

### 5.3 互換性・依存

- フロント: Phaser 3.80（`textures.addCanvas`、`anims.create`）/ Vite 5.2 / TypeScript 5.4
- 追加ライブラリ: なし（Canvas API はブラウザ標準）
- ハードコーディング禁止: 新たな設定値は `gameConfig.ts` に集約する

### 5.4 セキュリティ

- 新規外部通信なし。Canvas 描画はクライアント側のみ。
- XSS 等の入力は存在しないため追加の対策は不要。

## 6. 制約・前提条件

- Phaser 3 の `textures.addCanvas` で生成したテクスチャからアニメーションを作成可能であることを前提とする。
- `PLAYER_SPRITE_W = 32`、`PLAYER_SPRITE_H = 48` は変更しない（スポーン位置算出に使用）。
- コミット前にクルトワ（security-engineer）レビュー必須。

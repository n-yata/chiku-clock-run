## ブラウザ実プレイ計測（**Pages デプロイ後にシャビが実施**）

ローカル dev サーバーはこのプロジェクトでは起動しない運用（シャビ指示）。`main` への push → GitHub Actions → Pages デプロイ後、シャビが実 URL で動作確認する。

| 指標 | 目標 | 計測方法 |
|------|------|---------|
| 描画 fps | 60 維持 | DevTools Performance タブ 5 秒記録 |
| 初回ロード時間 | < 5 秒 | DevTools Network `Disable cache` ON で再読込、`DOMContentLoaded` |
| 入力レイテンシ | 体感 < 100 ms | プレイ感で判定 |
| Golden path | 起動 → 移動 → 段差越え → 隙間ジャンプ → ゴール → クリア表示 → R リスタート | 手動 3 周 |
| 落下リスポーン | 隙間落下後 < 1 秒で復帰 | 手動で隙間に落ちる |
| クリア中の入力無効化 | 左右・ジャンプ無視、R のみ受理 | クリア後に各キー押下 |

### 確認手順（シャビ用）

1. `main` に push → GitHub Actions の `Deploy to GitHub Pages` ワークフロー成功を待つ
2. `https://<owner>.github.io/<repo>/` を開く
3. 上記 Golden path を 3 回プレイ
4. 違和感があれば共有 → Q6（ステージ寸法）/ Q7（カメラ lerp）/ Q8（クリアテキスト）の調整候補

## 失敗時のフォールバック（design.md §9.3 再掲）

| 症状 | 対策 |
|------|------|
| 60 fps 未達 | ステージ寸法縮小（`cols=120 → 90`）。地面 sprite 数の削減 |
| 初回ロード 5 秒超過 | バンドル縮小余地は薄い（Phaser 自体が 1.1 MB 超）。CDN 配信不安定なら時間帯変えて再計測 |
| カメラ追従が硬い / 緩い | `CAMERA_LERP_X/Y`（現 0.1）を 0.05〜0.2 で調整 |
| 高段（N=3）に届かない | `JUMP_VELOCITY` を -480〜-500 に微調整、または高段 col 幅縮小 |

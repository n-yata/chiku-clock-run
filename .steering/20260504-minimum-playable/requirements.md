## 1. 背景

### 1.1 現状

- 初回コミット `567d2d3 chore: initial scaffold from webapp-template` のみ。スキャフォールド直後。
- 実装は最小雛形のみ:
  - `src/main.ts` … 960×540 固定、重力 800、Arcade Physics、`Phaser.Scale.FIT` で配置
  - `src/scenes/BootScene.ts` … プレースホルダ生成（赤い四角 32×48 のプレイヤー、茶色 64×32 の地面）→ `GameScene` へ遷移
  - `src/scenes/GameScene.ts` … 1画面分の地面1段、左右移動（200px/s）、Space/↑ でジャンプ（-450px/s）。ステージ・ゴール・カメラ追従なし
- 永続的ドキュメント（`docs/`）は `template/` のみで実体ゼロ。`.steering/` も同様。
- GitHub Actions / Pages デプロイ動線は `.github/workflows/` に存在する想定だが本スプリントで初通し予定。

### 1.2 やりたいこと

ブラウザで URL を開けば「**1ステージを左右移動 + ジャンプで進み、ゴールに触れるとクリア表示**」までを遊べる最小版を作り、GitHub Pages にデプロイして公開動線を初通しする。敵・コイン・BGM・複数ステージは v0.2 以降に送る。

## 2. ゴール

### 2.1 主目的

- 公開 URL を開くだけで、追加操作なしに `GameScene` まで到達して即プレイできる
- 1ステージを踏破できる（横スクロール + 段差 + 隙間 + ゴール）
- ターゲット値:
  - Before（現状）: 1画面・地面1段のみ。スクロールなし、ゴールなし
  - After（v0.1）: 横スクロール対応・段差2〜3段・隙間1〜2箇所・ゴール踏破でクリア表示

### 2.2 副次目的

- ステージ定義・カメラ追従・ゴール判定・リスタートの基本パターンを確立し、v0.2（敵・コイン）の土台にする
- GitHub Actions → Pages のデプロイ動線をリリースで一度通し、以降のスプリントで安心して push できる状態にする
- 物理パラメータ・ステージ定義の外出し方針を決め、ハードコーディング禁止ルール（`CLAUDE.md`）に沿った構造を確立する

## 3. スコープ

### 3.1 含むもの

- 1ステージ分のレベル定義（横スクロール、段差 2〜3 段、隙間 1〜2 箇所、ゴール）
- プレイヤー操作: 左右移動、ジャンプ、空中での慣性、地面接地判定
- カメラ追従（ステージを横スクロール）
- ゴール判定 + クリア表示 + リスタート（R キー）
- 落下リスポーン（画面下に落ちたらステージ最初に戻る）
- プレースホルダ画像の整理: プレイヤー / 地面 / ゴール（現状の `BootScene` 生成方式を踏襲）
- 影響を受けるファイル: `src/main.ts`, `src/scenes/BootScene.ts`, `src/scenes/GameScene.ts`, 新規ステージ定義モジュール
- GitHub Pages デプロイ確認（`.github/workflows/` 経由）
- 永続的ドキュメントの**最小限の起こし**: `docs/architecture.md` / `docs/repository-structure.md` のたたき（残りは後続スプリントへ）

### 3.2 含まないもの

- 敵キャラクター、踏みつけ・ダメージ
- コイン、スコア、ライフ、残機
- BGM / SE
- 外部アセット導入（プレースホルダの色付き四角のまま）
- 複数ステージ、ステージセレクト、ワールドマップ
- モバイルタッチ操作（キーボードのみ）
- セーブ/ロード、進行管理
- タイトル画面、ポーズ画面（最小化のため省略）
- `docs/` 配下の全6ファイル整備（v0.1 では architecture / repository-structure の2本のみ薄く起こす）

## 4. 機能要件

### 4.1 ゲーム起動 〜 プレイ 〜 クリア

1. ユーザーがブラウザで公開 URL を開く
2. `BootScene` がプレースホルダテクスチャを生成し `GameScene` へ遷移
3. `GameScene` がステージ定義を読み込み、地形・ゴールを配置
4. プレイヤーはステージ左端付近にスポーン、操作説明テキストを画面左上に表示
5. 左右キーで水平移動、Space/↑ でジャンプ
6. カメラがプレイヤーを追従して横スクロール
7. 段差・隙間を越えて右へ進む。隙間に落下した場合は §4.3 のリスポーン挙動
8. ゴール（最右端のオブジェクト）に触れるとクリア判定
9. 画面中央に「クリア！」「R で最初から」を表示。プレイヤーの操作は無効化
10. R キーで `GameScene` がリスタート

### 4.2 ステージ定義

- 横長: 画面幅の **3〜5倍程度**（例: 960 × 4 = 3840 px）
- 地形要素: 地面（連続）+ 段差 2〜3 段 + 隙間 1〜2 箇所 + ゴール
- 定義の保持方法は `design.md` で確定（候補は §8 Q1 参照）

### 4.3 落下時の挙動

- プレイヤーが画面下端の閾値（ステージ高さ + 余白）より下に落ちたら、ステージ最初の位置にリスポーン
- 残機・ライフ・ダメージ概念は持たない（v0.2 以降）

### 4.4 既存機能の互換要件

- `BootScene.preload()` のテクスチャ動的生成方式は踏襲（外部アセット非使用方針のため）
- 現状の物理パラメータ（重力 800、`PLAYER_SPEED=200`、`JUMP_VELOCITY=-450`）は**出発点として維持**。プレイ感調整のための微修正は実装中に許容
- `vite.config.ts` の `VITE_BASE_PATH` 経由での base 解決は維持（GitHub Pages 配下用）

## 5. 非機能要件

### 5.1 パフォーマンス

- 描画: 60 fps を維持（DevTools の Performance タブで確認）
- 初回ロード: GitHub Pages 上で 5 秒以内（モダン回線・キャッシュなしで）
- 入力レイテンシ: 体感 100 ms 以内（キー押下から自機反応まで）

### 5.2 信頼性

- リソース読み込み失敗時はコンソールにエラー、画面はクラッシュさせず復帰可能な状態を維持
- 画面外落下は即時リスポーン（無限落下を発生させない）
- ゲーム中の例外で操作不能になった場合、R キーでリスタートできる動線を維持

### 5.3 互換性・依存

- フロント: TypeScript 5.4 + Vite 5.2 + Phaser 3.80（**追加依存なし**）
- 対応ブラウザ: 最新 Chrome / Edge / Firefox / Safari
- ハードコーディング集約先:
  - GitHub Pages の base パス → `vite.config.ts` の `process.env.VITE_BASE_PATH`
  - ステージ定義・物理定数 → 専用モジュール（`src/config/` または `src/stages/` を `design.md` で確定）
  - URL / シークレット類は本スプリントでは発生しない（バックエンドなしのため）

### 5.4 セキュリティ

- バックエンドなし、外部 API 呼び出しなし、ユーザー入力はキーボードのみ → 攻撃面は最小
- 外部 CDN や外部アセットの新規読み込みを行わない（依存追加禁止）
- CSP は GitHub Pages のデフォルトに依存。HTML の `<meta http-equiv="Content-Security-Policy">` 追加可否は `design.md` で評価
- ユーザー生成データ・永続化なし → XSS / Injection の主要面は発生しない想定

## 6. 制約・前提条件

- バックエンドを持たない静的サイト方針（`CLAUDE.md` / `docs/architecture.md` の方針に準拠）
- ハードコーディング禁止: ステージ定義・物理定数・base パスは定数モジュール / 環境変数で集約
- コミット前にクルトワ（security-engineer）レビュー必須（CLAUDE.md ルール）
- 各ドキュメント（requirements / design / tasklist）はシャビ承認後に次フェーズへ進む
- 公開対象: GitHub Pages（プライベートデータなし、誰でも閲覧可能）

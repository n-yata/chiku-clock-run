# 要求内容

## 概要

`CHIKU CLOCK RUN` の画面・用語・配布メタデータから、既存ゲーム作品を想起させる残存要素を取り除き、時計仕掛けの冒険を軸にしたオリジナルのブランドとゲーム表現へ統一する。

## 背景

プレイヤーキャラクターとタイトルは一部オリジナル化されているが、現在の実装には以下の名残が残っている。

- プロジェクト名、PWA 名、ページタイトル、保存キー、README / 永続ドキュメントに `mario-game` または「マリオ風」「クリボー風」が残る
- PWA アイコンが赤地に白い `M` で、独自ブランドとして識別しにくい
- 敵、赤い旗型ゴール、コイン、キノコ、ファイアフラワー、スター、火球の造形・命名・ゲーム内説明が既存作品の定番表現に寄っている
- ステージデータと音声イベント名にも、同じ題材を前提にした名称が残る

公開作品として独自性を明確にするため、タイトルだけでなく遊んで目に入る要素、アプリのインストール表示、コード上のドメイン語彙、説明文書を同じ世界観に揃える必要がある。

## 世界観方針

- ブランド名は既存タイトル `CHIKU CLOCK RUN` を正式名称として維持する
- 意匠は「時計工房を駆ける探検家」「歯車・ぜんまい・時間エネルギー」を中核モチーフとする
- 横スクロール、ジャンプ、敵への踏みつけ、収集、成長、射撃、一定時間の無敵という既存の操作・ゲームバランスは維持する
- 一般的なゲーム機能ではなく、固有作品を想起させる名称・視覚モチーフ・ブランド表示を変更対象とする

## 実装対象の機能

### 1. ブランド表示と配布メタデータのオリジナル化

- HTML タイトル、PWA manifest、package メタデータ、README、プロジェクト説明を `CHIKU CLOCK RUN` / `chiku-clock-run` に統一する
- `mario-game` や「マリオ風」を公開表示および現在仕様を説明する永続ドキュメントから除去する
- 保存キーは新ブランドに合わせて更新し、旧キーが残っても起動が壊れない扱いを設計で定義する

### 2. PWA アイコンの独自意匠化

- 赤地に白い `M` のアイコンを廃止する
- `CHIKU CLOCK RUN` の時計・歯車モチーフを用いた独自アイコンを 192px / 512px / maskable 512px で生成する
- 生成スクリプトと生成済みアイコンの双方を新意匠へ揃える

### 3. ステージ上の常時表示オブジェクトの独自意匠化

- 敵の「クリボー風」シルエットと説明を、時計工房の障害物として成立する独自キャラクターへ変更する
- 赤い旗型ゴールを、時計塔ビーコン等の独自ゴール表現へ変更する
- コインの見た目・HUD 表記・説明を、歯車片等の時計世界に合う収集物へ変更する
- 地面アセットについても全体意匠との不整合がないか確認し、必要な場合は同時に差し替える

### 4. パワーアップと攻撃表現の独自意匠化

- キノコ、ファイアフラワー、スター、火球を、ぜんまい・コイル・時間結晶・エネルギー弾等のオリジナル表現へ置き換える
- 取得時の効果（成長、射撃能力、一時無敵）と既存ゲームバランスは維持する
- テクスチャキー、イベントキー、変数・関数名、ステージコメント、表示文言を新しいドメイン語彙に統一する

### 5. 仕様書とテストの整合

- `docs/`、`README.md`、運用ルール文書の現在仕様記述をオリジナル設定に合わせて更新する
- E2E テストは変更後の可視オブジェクトを実際に検証し、旧色や旧名称だけを前提にした判定を残さない
- 過去スプリントの履歴文書は履歴として改変せず、現在仕様を表す文書と実装を対象にする

## 受け入れ条件

### ブランド表示と配布メタデータ

- [ ] 起動時タイトル画面、ブラウザタイトル、インストール可能アプリ名が `CHIKU CLOCK RUN` として整合する
- [ ] 現在仕様を表すコード、`README.md`、`docs/`、`AGENTS.md`、`CLAUDE.md` に `mario-game`、`Mario-like`、「マリオ風」、「クリボー風」が残っていない
- [ ] `mario-game` 由来の sessionStorage キーを直接利用し続けず、旧キーが存在しても例外や不正ステージ遷移を起こさない

### PWA アイコン

- [ ] `public/icons/` の 3 種のアイコンが赤地に白い `M` ではなく、時計・歯車モチーフの独自意匠になる
- [ ] `npm run generate-icons` の再実行後も同じ新意匠が生成される

### ゲーム画面の独自性

- [ ] 敵、ゴール、収集物が時計工房の世界観に沿う独自の見た目と用語で表示される
- [ ] キノコ、ファイアフラワー、スター、火球に相当する既存意匠・名称が、画面表示・現在のソース命名・仕様記述に残っていない
- [ ] 収集、成長、射撃、無敵、踏みつけ、ゴール、各ステージのクリア進行が変更前と同じ機能として動作する

### 品質と文書整合

- [ ] `docs/` と `README.md` が変更後の名称・見た目・操作を説明している
- [ ] 変更した可視要素を対象にした E2E 検証が存在し、意味のある入力と期待描画または状態を確認する
- [ ] `npm run typecheck`、`npm run build`、`npm run test:e2e` が成功する
- [ ] コミットを行う場合は、全変更ファイルを対象としたクルトワのセキュリティレビューで Critical / High 指摘が解消されている

## 成功指標

- 公開画面・インストール表示・現行文書から特定既存作品の名称および代表的な視覚記号が除去される
- ゲームを見たプレイヤーが `CHIKU CLOCK RUN` の時計仕掛けの世界観として認識できる
- 操作性と既存の進行機能を維持したまま、既存 E2E を更新・通過できる

## スコープ外

以下はこのフェーズでは実装しない。

- 新しいステージの追加、ステージ構造または難易度の全面変更
- 操作方式、物理パラメータ、ライフ数、パワーアップ効果時間等のゲームバランス変更
- BGM の全面作曲変更または外部音声アセット導入
- リポジトリ名や GitHub Pages 公開 URL 自体の移行作業
- `.steering/` 配下に保存されている過去スプリント履歴の遡及的な文言書き換え

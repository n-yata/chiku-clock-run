## 1. 背景

### 1.1 現状

- v0.2 + モバイル操作改善が完了し、敵・コイン・スコア HUD・レスポンシブ対応まで実装済み（コミット `f2280f3` 時点）
- **音がまったく鳴らない**: ジャンプ・コイン取得・敵踏みつけ・ミス・ゴール達成のいずれも無音
- `GameScene.ts` の `onEnemyOverlap`（踏みつけ）/ `onCoinOverlap` / `handleMiss` / `onGoalHit` にはすでに SE 追加を想定したプレースホルダコメント（`// TODO: SE`）が残っている
- 現行アーキテクチャは 100% 静的サイト（バックエンドなし）。外部 CDN フェッチ禁止
- バンドルサイズ現状: 1,490 kB（gzip 343 kB）。上限 1.5 MB に残り 10 kB しかない（音声ファイルを加えると超過リスクあり）
- テクスチャは `BootScene.generateTexture()` でプログラム生成しており、外部アセットファイルに依存しない設計方針

### 1.2 やりたいこと

ジャンプ・コイン取得・敵踏みつけ・ミス・ゴール達成の効果音（SE）と、ステージ再生 BGM を追加し、「音が鳴るゲーム」として体験を向上させる。
外部音声ファイルは持たず、**Web Audio API によるプログラム合成**でバンドルサイズを維持しながら実現する方向を基本方針とする（Q1 で設計確定）。

---

## 2. ゴール

### 2.1 主目的

- SE 5 種（ジャンプ・コイン取得・踏みつけ・ミス・ゴール）が各アクション時に鳴ること
- BGM がステージ開始と同時にループ再生され、ミス・リスタート時にもシームレスに継続すること
- バンドルサイズ < 1.5 MB を維持すること（外部ファイル追加なし方針の場合、自動的にクリア）

### 2.2 副次目的

- 音量調整・ミュート切り替えは v0.3 以降に持ち越す（今回はスコープ外）
- 音合成ロジックを `src/audio/` に独立モジュールとして切り出し、将来の差し替えや追加を容易にする

---

## 3. スコープ

### 3.1 含むもの

- **SE 5 種の実装**: ジャンプ・コイン取得・踏みつけ（撃破）・ミス・ゴール達成
- **BGM 1 曲の実装**: ステージ BGM（ループ再生）
- **音合成モジュール**: `src/audio/AudioManager.ts`（Web Audio API ベース、またはバルベルデ設計に従う）
- **GameScene.ts への統合**: 各イベントコールバックから AudioManager を呼び出す
- **gameConfig.ts への定数追加**: SE の周波数・長さ・BGM テンポ等のパラメータ

### 3.2 含まないもの

- 音量調整 UI・ミュートボタン（v0.4 以降）
- 外部音声ファイル（MP3 / OGG / WAV）のバンドル同梱（Q1 で否定される場合を除く）
- iOS Safari 固有の AudioContext unlock 対策は Q2 として設計に委ねる
- 複数ステージ・タイトル画面（別スプリント）

---

## 4. 機能要件

### 4.1 SE 再生フロー

各ゲームイベントで対応する SE が鳴る:

| イベント | SE | 発生箇所 |
|---------|-----|---------|
| ジャンプ | 短い上昇音 | `update()` のジャンプ判定直後 |
| コイン取得 | 明るい高音 | `onCoinOverlap()` |
| 敵踏みつけ撃破 | 低めのドン音 | `onEnemyOverlap()`（踏みつけ確定時） |
| ミス（敵接触 / 落下） | 下降音 | `handleMiss()` |
| ゴール達成 | ファンファーレ風（複数音） | `onGoalHit()` |

### 4.2 BGM 再生フロー

1. `GameScene.create()` 完了直後に BGM ループ再生を開始する
2. ミスによる `window.location.reload()` でページリロードされても、再ロード後の `create()` で自動的に再開する（リロード方式のため自然に解決）
3. ゴール達成後はプレイヤー操作が無効化されるが BGM は継続（止めるかは Q3 として設計に委ねる）

### 4.3 既存機能の互換要件

- v0.2・モバイル操作改善で実装済みのすべての既存機能（敵 AI・コイン・HUD・タッチ操作・レスポンシブ）は変更なし・動作維持
- `src/config/gameConfig.ts` への定数追加は**既存定数を変更しない**（末尾追記のみ）
- `GameScene.ts` の既存ロジックへの影響は最小限（呼び出し追加のみ）

---

## 5. 非機能要件

### 5.1 パフォーマンス

- 60 fps 維持（BGM ループ再生中も変化なし）
- バンドルサイズ < 1.5 MB（音声ファイル追加なし方針であれば自動クリア）
- SE 発火から再生開始までのレイテンシ < 50 ms（Web Audio API 使用時は自然に達成）

### 5.2 信頼性

- **iOS Safari の AudioContext 自動再生制限への対応**: ユーザー操作（タッチ / キー入力）後に AudioContext を resume する仕組みを組み込む（設計詳細は Q2 としてバルベルデに委ねる）
- SE が鳴らなくてもゲームプレイには影響しない（音声なしで完全に動作）

### 5.3 互換性・依存

- フロント: **追加 npm 依存なし**（Web Audio API はブラウザ標準 API）
- 対応ブラウザ: Chrome / Edge / Firefox / Safari 最新版（Web Audio API サポート済み）
- ハードコーディング禁止: SE パラメータ（周波数・持続時間・波形タイプ等）はすべて `src/config/gameConfig.ts` に集約

### 5.4 セキュリティ

- 外部 URL へのフェッチなし（CSP `default-src 'self'` 維持）
- Web Audio API はブラウザ内完結。外部通信なし
- `add.text()` 等への動的文字列挿入なし（既存方針継続）

---

## 6. 制約・前提条件

- **バックエンドなし**: 100% 静的サイト。音声ファイルをバンドルに含める場合はサイズに注意
- **バンドルサイズ上限 1.5 MB**: 音声ファイル追加は現状残り 10 kB しかないため、ファイル同梱は実質困難。プログラム合成を基本方針とする
- **CSP**: 現行の `default-src 'self'` を変更しない（外部音源ファイル取得は禁止）
- **コミット前クルトワレビュー必須**（CLAUDE.md）
- **dev サーバー自走禁止**（auto memory）: 動作確認は Pages デプロイ後にシャビが行う

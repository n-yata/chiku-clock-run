# 設計 — UIチープさ抜本改善（リッチ化）

優先度順に P1→P3 で進める。各フェーズ独立で、完了ごとにスクショ検証。

---

## P1: HUD 全面作り直し（最優先・即効性最大）

### 問題の構造
- HUD はワールド座標に配置し `layout()` で逆ズーム補正している → **カメラズームが HUD 文字まで拡大しボヤけ・見切れ**。
- 4行（STAGE/歯車/ライフ/操作説明）が y=16/40/64/88 と近接し 24px 文字が重なる。

### 解決方針
1. **専用 UI カメラを導入**（`this.cameras.add`）。
   - メインカメラはズーム維持。UI カメラは zoom=1・scroll 固定。
   - メインカメラは HUD オブジェクトを `ignore`、UI カメラはゲーム world を `ignore`。
   - これで HUD は等倍・鮮明・スクリーン座標で素直に配置でき、逆ズーム math を撤廃。
2. **HUD を `Container` + パネル化**。
   - 左上に半透明角丸パネル（`Graphics`）を敷き、その上に STAGE / 歯車 / ライフ を配置。
   - 行間を text の実高さベースで確保（重なり解消）。
   - 歯車・ライフはアイコン（既存 gear テクスチャ / ♥）+ 数値の形に。
3. **操作説明**は下部中央に小さめ、開始時のみ表示しフェード（既存ロジック流用）。
4. `HudManager` の `layout()` を UI カメラ前提に書き換え、`makeHudText` のスタイルを整理。

### 変更ファイル
- `src/game/HudManager.ts`（UIカメラ対応・パネル・アイコン・レイアウト）
- `src/scenes/GameScene.ts`（UIカメラ生成・ignore 設定・HUD生成の接続）
- `src/config/gameConfig.ts`（HUDパネル色/余白/アイコンサイズ等の定数追加）

### E2E 影響
- `renders sprite assets` 等は world 描画のピクセルを見る。UI カメラは別レイヤなので world 描画は不変 → 既存アサーションは維持される想定。HUD 位置を見るテストがあれば契約更新。

## P2: 背景リッチ化（継ぎ目除去 + 世界観）

### 問題
- `tileSprite(bgTile)` の繰り返し境界が見える。全体が暗く濁る。

### 解決方針
1. **bgTile テクスチャをシームレス化**（`buildBackgroundTexture` を上下左右ループ可能なパターンに。歯車モチーフを tile 端で連続させる）。
2. **多層パララックス**で奥行き：遠景（大歯車をうっすら回転 or 固定）＋ 近景タイル。色は時計工房＝真鍮/琥珀のアクセント + 沈んだ青のベースでコントラストを上げる。
3. ビネット or 上下グラデーションで安っぽい一様塗りを回避。

### 変更ファイル
- `src/scenes/spriteSheets.ts`（背景テクスチャ生成のシームレス化・明度調整）
- `src/scenes/GameScene.ts`（パララックス層追加）
- `src/config/gameConfig.ts`（背景配色定数）

## P3: キャラ・敵の抜本リデザイン + 演出 juice

### 方針（厳守）
- **既存シルエットを捨てる**。チク・敵をゼロから設計。
- 表示サイズ（display size / native テクスチャ解像度）を見直し、ディテールが視認できるサイズに。
  - native テクスチャ解像度を上げ（縮小しすぎない）、カメラズームでも崩れないようにする。

### チク（プレイヤー）新設計の方向（たたき台。スクショ確認で調整）
- 「時計工房の見習い職人」。大きめの頭身でアイコニックなシルエット。
- 識別点を1つに絞る（例: 発光するモノクル/片眼鏡 or 歯車の翼）。スカーフ等の動く要素で生き生きさせる。

### 敵 新設計
- ぜんまい仕掛けロボを継続しつつシルエットを刷新（頭の鍵・発光する単眼など識別性を上げる）。

### 演出 juice（既存 ParticleManager / CameraController 活用）
- 取得（歯車）: スケールポップ + パーティクル強化。
- 撃破: つぶれ + 破片 + ヒットストップ（既存）を強める。
- 着地/ジャンプ: スクワッシュ&ストレッチ（tween scaleX/Y）。
- クリア: 既存 celebrate を強化。

### 変更ファイル
- `src/scenes/spriteSheets.ts`（チク・敵の描画を新設計に）
- `src/config/gameConfig.ts`（スプライトサイズ・配色）
- `src/scenes/GameScene.ts` / `src/game/*`（表示サイズ・juice tween 接続）

### E2E 影響
- `fits a fire-size player ...` は displayHeight=84 を前提（big=PLAYER_SPRITE_H*BIG_SCALE）。サイズ変更時はこの契約と body サイズの整合を必ず確認・更新。
- 色ベースのピクセル検査があれば新配色に合わせて閾値/期待色を更新。

## 検証フロー（全フェーズ共通）
1. 実装 → `npm run typecheck` 緑。
2. `tests/e2e/_shot.spec.ts`（一時）でスクショ取得 → 目視で改善確認。
3. フェーズ完了時に `npm run build` / `npm run test:e2e` 緑。
4. 全フェーズ後に `_shot.spec.ts` を削除し、クルトワ（security-engineer）レビュー → コミット。

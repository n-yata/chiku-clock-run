# 要求内容

## 概要

ステージ2・3の敵（巻きネジ障害機）を増やし、地形（床の隙間・段差）も難化させることで、
ステージが進むごとに段階的に手応えが増す難易度カーブを実現する。

## 背景

- 現状の敵数は stage01=4 / stage02=5 / stage03=8 体で、stage02→03 の差は大きいが
  stage01→02 の差（4→5）が小さく、難易度カーブがなだらか過ぎる。
- 敵の配置上限が `GameScene.ts` で 1〜8 体に制限されており、stage03 が既に上限のため
  「最終ステージをさらに手強く」する余地がない。
- 敵数だけでなく、床の隙間（落下リスク）と段差（立体的なルート）を増やすことで、
  プレイ体験として明確に「奥のステージほど難しい」と感じられるようにしたい。

## 実装対象の機能

### 1. 敵配置上限の引き上げ
- `GameScene.ts` の `'E' count must be 1..8` 制約を 1〜14 体に緩和する。
- stage03 で 8 体を超える敵を配置できるようにする。

### 2. stage02 の難化（敵＋地形）
- 敵: 5 → 8 体に増加。
- 地形: 床の隙間・段差を増やし、難易度スコアを引き上げる。
- intermediate ロールにふさわしい中盤の手応えにする。

### 3. stage03 の難化（敵＋地形）
- 敵: 8 → 12 体に増加。
- 地形: stage02 を上回る隙間・段差を配置。
- final ロールにふさわしい最難関にする。

### 4. 段差はジャンプで到達可能な位置に配置
- これまでジャンプしても届かない浮遊足場が多かった問題を是正する。
- 段差（着地できる足場）は、直下の立ち面（地面 or 下段足場）から最大 3 タイル以内に置く。
- 高い足場は「地面 → 中段 → 上段」の階段状にし、中段を踏み台に上段へ届くようにする。
- 単独で 4 タイル以上浮いた到達不能な足場を残さない。

### 5. stage01 は現状維持
- 入門ステージとして敵 4 体のまま据え置き、段階差を明確にする。

## 受け入れ条件

### 敵配置上限
- [ ] `GameScene.ts` の上限が 14 に引き上げられている
- [ ] stage03 で 9 体以上の敵がエラーなくスポーンする

### 難易度の段階性（stageValidation の検証を全てパス）
- [ ] `validateDifficultyProgression` がエラーを返さない
- [ ] 難易度スコアが stage01 < stage02 < stage03 で厳密に増加
- [ ] 隙間数・段差数が後段ステージで減少しない
- [ ] 各ステージの `difficultyScore >= difficulty.minimumScore`

### ステージ整合性（buildStage の検証を全てパス）
- [ ] 全 `E` の真下が `#`（床上配置）になっている
- [ ] `validateCriticalPathClearance` がエラーを返さない（必須走路のクリアランス維持）
- [ ] プレイヤースポーン左右のクリアランスが保たれている

### 段差の到達性
- [ ] 全ての足場が、直下の立ち面から 3 タイル以内 or 階段経由で到達できる
- [ ] 4 タイル以上単独で浮いた到達不能な足場が存在しない
- [ ] 実プレイで stage02・03 の全足場にジャンプで乗れることを確認

### 動作確認
- [ ] `npm run build`（型チェック含む）が通る
- [ ] 実際にプレイし、stage02・03 が体感で難しくなっていることを確認

## 成功指標

- 敵数: stage01=4 / stage02=8 / stage03=12（明確な段階差）
- 難易度スコアが 3 ステージで単調増加
- ビルド・検証がすべてグリーン

## スコープ外

以下はこのフェーズでは実装しません:

- 新しい敵タイプ（速い敵・飛ぶ敵など）の追加 — 既存の巻きネジ障害機のみ
- 敵 AI ロジックの変更（`EnemyManager` は変更しない）
- 新ステージ（stage04 以降）の追加
- 難易度スコア計算式そのものの変更

- **決定**: 新しい敵タイプ（速い/飛ぶ等）の追加は本スプリントに含めず、次スプリント
  `20260601-enemy-types`（仮）で設計から実施する。
- **理由**: 敵タイプ追加は新スプライト素材・`TileChar` 型拡張・新 AI 実装を伴い、本タスク
  （tile データ調整中心）とレイヤーが異なる。混在させると難易度カーブ調整の完了が遅れる。
- **シャビ承認**: あり。

## 2026-06-01: elevated 数を設計値から下方修正（9/10 → 6/8）

- **決定**: design.md の目標 elevated（stage02=9 / stage03=10、score 34/42）を、
  実装では stage02=6 / stage03=8（score 28/38）に変更した。
- **理由（技術的制約）**:
  - `validateCriticalPathClearance` は必須走路（床 row16）の頭上 3 タイルに `#` を禁止する。
  - 一方ジャンプ到達高さは約 3 タイル（126px）。よって「到達可能な高さ(≤3)の足場」は
    必須走路の真上に置けず、**ピット上（criticalPath 非対象列）にしか配置できない**。
  - ピット数（stage02=4 / stage03=5）に足場配置が律速されるため、elevated を 9/10 まで
    詰め込むと不自然な密集・到達性の破綻を招く。到達可能な踏み石を優先し数を抑えた。
- **影響**: 難易度の必須制約はすべて充足。
  - score 厳密増加: 8 < 28 < 38
  - gaps 非減少: 2 ≤ 4 ≤ 5、elevated 非減少: 0 ≤ 6 ≤ 8
  - 各 `minimumScore` 充足（stage02:28≥11 / stage03:38≥16）
- **検証**: 一時スクリプト（stageValidation と同一ロジック＋到達性チェック、実装後に削除）で
  全エラー 0 を確認。恒久的には e2e（game-visual.spec.ts）と stageValidation.ts で担保される。

## 2026-06-01: 床モデルを単層(row16)に統一

- **決定**: stage02/03 の旧二層床（row15+row16 + 複雑なブリッジ）を、stage01 と同じ
  単層床（row16）+ ピットのモデルに作り直した。
- **理由**: 旧構造は support 行が row15/16 混在で複雑、かつ高所足場が row8〜11 に浮いて
  到達不能だった。単層化で criticalPath を row16 に統一し、到達性設計を単純・確実にした。

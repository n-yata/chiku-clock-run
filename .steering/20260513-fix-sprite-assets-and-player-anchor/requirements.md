# 要求書: スプライトアセット表示とプレイヤー足元補正

## 1. 背景

### 1.1 現状

ローカル起動時に、地面やコインなど一部の外部 PNG アセットがゲーム画面上で期待どおり表示されない。
`BootScene` は `src/assets/images/*.png` を Vite import 経由で読み込み、`GameScene` は `TEX_KEY.ground` / `TEX_KEY.coin` を使ってタイルとコインを生成している。
スクリーンショット上では地面がワイヤー状の表示に見え、コインは HUD 上の枚数には反映されているが画面内に見えない。
また、プレイヤーがキノコやファイアフラワーで大きくなったとき、表示サイズ変更後に足元が床から浮いて見える。

### 1.2 やりたいこと

ローカル起動時でも地面・コインの画像が正しく表示されるようにする。
プレイヤーの状態変化で表示サイズが変わっても、足元が床面に接したままになるよう補正する。

---

## 2. ゴール

### 2.1 主目的

- `http://localhost:5173/` で地面タイルとコインが画像として表示される
- プレイヤーが `small` から `big` / `fire` に変化しても、足元の床接地位置が視覚的にずれない
- ターゲット値（参考）: 地面・コインの表示欠落あり → 表示欠落なし、拡大時の足元浮きあり → 足元浮きなし

### 2.2 副次目的

- アセット読み込み失敗時の原因を追いやすくする
- プレイヤー状態変更処理を、物理 body と表示サイズの整合が取れる形に保つ

---

## 3. スコープ

### 3.1 含むもの

- `BootScene` の画像アセット読み込み経路の確認と修正
- `GameScene` の地面・コイン生成処理の確認と必要な補正
- `GameScene.applyPlayerState()` 周辺のプレイヤー拡大・縮小時の足元位置補正
- 既存のステージ進行、敵、コイン取得、パワーアップ、ファイアボール挙動の維持

### 3.2 含まないもの

- 新規アセットの追加や絵柄の刷新
- ステージレイアウトの変更
- スコアシステムやライフシステムの仕様変更
- GitHub Pages デプロイ設定の変更

---

## 4. 機能要件

### 4.1 アセット表示

1. `BootScene.preload()` で地面・ゴール・コインの画像がロードされる。
2. ロード済みテクスチャを使って、`GameScene.buildStage()` が地面タイルを `TILE_SIZE` に合わせて表示する。
3. ロード済みテクスチャを使って、`GameScene.buildCoins()` がコインを `COIN_SPRITE_W` / `COIN_SPRITE_H` に合わせて表示する。
4. ロード失敗が発生した場合は、既存の `loaderror` ログで対象 key と src を確認できる。

### 4.2 プレイヤー状態変更

1. `small` / `big` / `fire` の表示サイズと Arcade Physics body サイズが一致する。
2. 状態変更前の下端座標を保持し、サイズ変更後も下端座標が同じになる。
3. パワーダウン時もプレイヤーが床や空中で不自然に跳ねたり沈んだりしない。

### 4.3 既存機能の互換要件

- ステージ定義文字（`#`, `C`, `P`, `G`, `E`, `M`, `F`, `S`）の意味を変えない
- `TEX_KEY` によるテクスチャキー抽象化を維持する
- `window.location.reload()` フォールバックと `scene.restart()` 経路の仕様を変えない

---

## 5. 非機能要件

### 5.1 パフォーマンス

- 追加処理はプレイヤー状態変更時とステージ構築時に限定し、毎フレーム処理を増やさない
- バンドルサイズ上限（`dist/assets/*.js` 合計 1.5 MB 以下）を維持する

### 5.2 信頼性

- アセット読み込み順序に依存した表示欠落を避ける
- Phaser の static body は表示サイズ変更後に `refreshBody()` で同期する

### 5.3 互換性・依存

- フロント: TypeScript / Vite / Phaser 3 の既存依存のみを使う
- バックエンド: なし
- ハードコーディング禁止: 新規 URL、エンドポイント、シークレット、AWS アカウント情報は追加しない

### 5.4 セキュリティ

- ユーザー入力、認証、外部通信は追加しない
- ローカル静的アセット参照のみを扱い、外部サービス URL は追加しない

---

## 6. 制約・前提条件

- ブラウザで動く静的 Web アプリとして維持する
- 画像アセットは既存の `src/assets/images/` または既存の公開アセット方針に沿って扱う
- 実装前に `design.md` と `tasklist.md` を作成し、シャビ承認後にコード修正へ進む
- コミット前はクルトワ（security-engineer）レビュー必須
